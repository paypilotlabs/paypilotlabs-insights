### Option A: metadata only (recommended)
Change: pyproject `authors`, `description` and `[project.urls]`; `frontend/package.json` name; root `package.json` name; `hooks.app_description` and `app_license`.
Unchanged: app name, package folder, routes, asset paths, doctypes.
Files: `pyproject.toml`, `package.json`, `frontend/package.json`, `insights/hooks.py`. Risk: low. No migration. Upstream merges stay easy.

### Option B: full rename to `paypilotlabs_insights`
Change: package folder `insights/` to `paypilotlabs_insights/`, `[project] name`, `hooks.app_name`, every `import insights` (141 files), every dotted path (187 files, including frontend API calls and `patches.txt`), `/assets/insights` (12 files), vite `outDir`, `pyproject [tool.bench.assets]`, `docker-compose.yml --install-app`, CI independence script, telemetry and security-check app names. Routes can stay `/insights`.
Existing sites would need a manual migration (`Installed Application`, `Module Def.app_name`, `DocType.module` stays). Every future upstream merge would conflict on every file.
Risk: high, for a name no customer sees.

**Recommendation: Option A.** The bench name `insights` already matches the PayPilotLabs product name "Insights". Option B adds risk and gives users nothing.
